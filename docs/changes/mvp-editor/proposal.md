## 为什么（起因）

用户日常用 XMind 做学习笔记（例如 106 个主题的 K8s 导图），遇到三个具体问题：

1. 节点里无法写代码（行内命令、多行 YAML），也无法在同一节点内混用粗体、颜色、字号。
2. 一级主题按创建顺序左右交替分布，不能把某个大主题挪到右边。
3. 实际上只需要向右生长的分支，左侧分支反而碍事。

飞书思维笔记的体验更接近需求，但用户希望有一个自己可控的本地工具。

## 意图

> ⚠️ 由 Claude 起草，请用户确认或改写。

做一个**本地运行、只向右生长**的思维导图编辑器，作为 XMind 在个人笔记场景下的替代。核心差异是**节点内容是真正的富文本**：能写行内代码和带语法高亮的多行代码块，能在同一节点内局部加粗、变色、调字号。导图存成本地 JSON 文件，用 Cmd+S 直接写回；已有的 .xmind 笔记可以导入。第一版只追求「每天记笔记够用且顺手」，不追求 XMind 的完整功能。

## 技术验证（2026-10-31 spike，代码在临时目录，未入库）

基于 `simple-mind-map@0.14.0-fix.3`：

- ✅ **代码格式**：插件把 Quill 的格式白名单写死在 `RichText.initQuillEditor()` 里，不含 `code` / `code-block` / `link`。加入白名单后：行内代码与多行代码块能正常渲染，节点尺寸计算正确；双击编辑时 Quill 能正确解析已有代码块；Shift+Enter 换行仍留在代码块内；保存的 HTML 完整；`getData(true)` → JSON → `setFullData()` 往返后格式不丢。
- ✅ **语法高亮**：存储时只保存纯文本代码块（`data-language` 记录语言），渲染后用 highlight.js 给 DOM 上色。上色只改颜色、不改文字，节点尺寸不受影响。用 Quill 把代码块语言设为 `yaml` 后，`data-language="yaml"` 在保存、JSON 往返、再次进入编辑后都保留。
- ✅ **粘贴**：往代码块里粘贴多行带缩进的 YAML，每行都留在代码块内，前导空格完整。
- ❌→🔧 **复制**：插件拦截了编辑态的 Cmd+C，用 `textContent` 拼接文本，代码块的多行内容会被**压成一行**（实测 `kind: ReplicaSetmetadata:  name: my-rs`）。改用 `quill.getText(range)` 可得到正确的多行文本（已实测），放进同一个补丁里修。
- ⚠️ **数据版本坑**：根数据缺少 `smmVersion`（或低于 0.13.0）时，插件会把所有富文本样式**清除**。导入 / 新建 / 读文件时必须保证带上版本号。
- ⚠️ **编辑态 Tab 被禁用**：插件把编辑态的 Tab 设成了空操作（非编辑态 Tab 是「新增子主题」）。代码块里要缩进需要补丁。
- ⏳ **.xmind 导入**：插件自带解析器，支持 XMind 8（content.xml）和 XMind Zen/2020+（content.json），**尚未用真实文件验证**。需要用户提供 K8s 那份 .xmind。

- ✅ **代码块内缩进**（实现时确认）：Quill 自带代码块内的 Tab / Shift+Tab 键位（2 个空格，支持多行选区）。但编辑态时库把 Tab 绑定成「结束编辑」，用配置项 `beforeShortcutRun` 让光标在代码块内时跳过它，不需要补丁。Shift+Enter 新行继承缩进需要补丁。

**打补丁方式**：用 `patch-package` 对锁定版本（精确版本号，不用 `^`）打最小补丁（格式白名单、代码块 Shift+Enter 继承缩进、复制保留换行）。备选方案是继承 `RichText` 并整段重写 `initQuillEditor`（约 130 行拷贝）。补丁的 diff 更小也更容易看懂，代价是升级库时要重新核对补丁。

## 需求差分

### ADDED Requirements

**MAP：导图结构、布局与编辑操作**

- **MAP-01** 新建的导图使用向右生长的逻辑结构图布局：任意子主题都位于其父主题右侧。
  - 验证：新建导图，添加 3 层、每层多个节点，检查每个子节点的 x 坐标都大于父节点（自动化测试 + 截图）。
- **MAP-02** 选中节点时，键盘可完成基本编辑：Tab 新增子主题，Enter 新增同级主题，Delete / Backspace 删除，方向键在节点间移动选中，双击或 F2 / 空格进入文字编辑，Esc 退出编辑。
  - 验证：浏览器中逐个按键操作并检查导图数据。
- **MAP-03** 拖拽节点可以改变它的父节点及同级顺序。
  - 验证：浏览器中把一个节点拖到另一分支下，检查数据结构变化。
- **MAP-04** Cmd+Z 撤销，Cmd+Shift+Z 重做，对增删、编辑文字、拖拽、改格式都生效。
  - 验证：每类操作各做一次，撤销后数据恢复、重做后再次生效。
- **MAP-05** 画布可以用触控板 / 滚轮平移和缩放；节点的子树可以折叠和展开。
  - 验证：浏览器中操作确认。

**TXT：节点内容与富文本**

- **TXT-01** 同一节点内的文字可以局部设置粗体、斜体、下划线、删除线、文字颜色、字号。在编辑态选中文字时出现浮动格式工具栏；Cmd+B / Cmd+I / Cmd+U 分别切换粗体、斜体、下划线。
  - 验证：在一个节点里对不同片段设置不同样式，保存并重新打开后样式保持不变。
- **TXT-02** 选中的文字可以设为行内代码（等宽字体、浅灰背景），可通过工具栏按钮或 Cmd+E 切换。
  - 验证：设置后保存并重新打开，`<code>` 保留且显示正确。
- **TXT-03** 节点内可以插入多行代码块：等宽字体，保留空格与缩进，过长的行自动折行（不截断、不溢出节点）。编辑代码块时：Shift+Enter 换行后仍留在代码块内，且新行自动继承上一行的前导缩进；Tab 增加一级缩进（2 个空格），Shift+Tab 减少一级；选中多行时 Tab / Shift+Tab 对每一行生效。粘贴多行文本到代码块、或从代码块复制出来时，换行与空格原样保留。
  - 验证：粘贴一段多行 YAML，检查缩进完整、节点框完整包住代码块；在缩进 4 格的行末按 Shift+Enter，新行以 4 个空格开头；Tab / Shift+Tab 对单行和多行选区都正确增减 2 个空格；选中 3 行代码 Cmd+C 后粘贴到终端 / 文本编辑器，仍是 3 行且缩进不变。
- **TXT-04** 代码块可以指定语言，至少支持 yaml、bash、json、python、javascript、typescript、go，按所选语言做语法高亮；未指定语言时不高亮。
  - 验证：同一段代码切换语言，高亮随之变化；保存并重新打开后语言选择保留。
- **TXT-05** 选中的文字可以设为超链接。非编辑态下 Cmd+点击链接文字，会在新标签页打开该链接。
  - 验证：设置链接、保存、重新打开后 Cmd+点击可以打开。
- **TXT-06** 每个节点可以附加一张图片，显示在文字上方，可通过粘贴或选择本地文件添加。图片以内嵌方式存进导图文件，不依赖外部路径。
  - 验证：添加图片后保存，把文件移到别的目录再打开，图片仍然显示。

**FILE：文件存取与导入**

- **FILE-01** 导图以 JSON 文件保存，扩展名为 `.mindmap.json`，内容为 simple-mind-map 的完整数据（含 `smmVersion`）。
  - 验证：自动化测试，序列化再反序列化后数据相等，`smmVersion` 存在。
- **FILE-02** Cmd+O 打开本地 `.mindmap.json` 文件。Cmd+S 把修改写回原文件；尚未关联文件的新导图首次 Cmd+S 时弹出另存为。Cmd+Shift+S 另存为。
  - 验证：Chrome 中打开文件 → 修改 → Cmd+S，用编辑器查看磁盘上的文件已更新。
- **FILE-03** 有未保存的修改时，页面标题显示未保存标记；此时关闭或刷新标签页，浏览器弹出离开确认。
  - 验证：修改后检查标题，尝试刷新页面会出现确认框。
- **FILE-04** 可以导入 `.xmind` 文件（XMind 8 及 XMind 2020 以后的格式），主题的树结构和文字（含换行）完整导入，导入结果作为一个尚未保存的新导图打开。
  - 验证：导入用户提供的 K8s .xmind，普通主题数与原文件一致（用户提供的 K8s.xmind 的 content.json 中为 96 个主题，无概要 / 自由主题），抽查若干多行节点的文字。
